# Tech-Talk

## Etapa 1 — Contexto

Pergunte antes de começar:

1. Qual é o tema?
2. Objetivo: ensinar algo novo, compartilhar aprendizado de um bug, apresentar uma ferramenta ou discutir uma abordagem?
3. Quanto tempo disponível?
4. Já tem roteiro ou começa do zero?

## Etapa 2 — Roteiro sugerido

Com base nas respostas, monte um roteiro com esses blocos:

| Bloco | Duração sugerida | Conteúdo |
|---|---|---|
| Abertura | 1–2 min | Contexto e por que o tema importa para o squad |
| Problema / motivação | 3–5 min | Qual dor ou situação gerou esse conhecimento? |
| Conteúdo principal | variável | Explicação, demo ao vivo ou discussão |
| Aplicação prática | 2–3 min | Como o time pode usar isso no Fretadão? |
| Encerramento | 1–2 min | Resumo rápido + espaço para perguntas |

Adapte os blocos conforme o tempo disponível. Para temas mais densos, reduza a abertura e amplie o conteúdo principal.

## Etapa 3 — Resumo pós-apresentação

Ao final do Tech-Talk, pergunte:

- O Tech-Talk já foi apresentado?
- Quais foram os pontos principais discutidos?
- Houve perguntas ou insights relevantes do time?

Com isso, gere o resumo para registrar no canal do squad ou ClickUp:

```
**Tech-Talk: [Tema]**
Apresentado por: [Nome] | Data: [Data]

**Resumo:**
[2–3 parágrafos com os pontos principais]

**Principais aprendizados:**
- [item]
- [item]
- [item]

**Materiais:**
- [link, repositório ou referência, se houver]
```

## Regras

- O Tech-Talk não é avaliação de performance — é espaço seguro para compartilhar e aprender junto.
- Prefira temas com conexão ao trabalho do squad, mas temas abstratos também têm valor.
- O resumo deve sempre ser registrado no canal do squad ou ClickUp para quem não pôde participar (PRO-TEC-002, seção 4.12).
